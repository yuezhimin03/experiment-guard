# 方法说明

ExperimentGuard 的目标不是替代专业统计平台，而是把游戏版本实验中最容易遗漏的检查做成可复现流水线。

## 决策顺序

1. **先检查 SRM**：按期望 50/50 分流做 1 自由度卡方检验。`p < 0.001` 时停止解读效果，优先检查曝光日志、实验桶和去重逻辑。
2. **再看护栏**：崩溃用户率采用 `+0.5pp` 非劣界；付费率采用 `-0.3pp` 非劣界。判定使用差值 95% 置信区间，不只看 p-value。
3. **再看主指标**：D7 留存使用双侧两比例 z 检验，差值置信区间使用非合并标准误。
4. **控制提前偷看**：用 O'Brien-Fleming 型边界按当前信息比例收紧早期阈值。
5. **最后给业务建议**：只有分流、护栏、主指标方向、区间与序贯阈值同时通过，才建议推广。

## CUPED

人均游戏时长用实验前时长作为协变量：

`Y_adj = Y - theta * (X - mean(X))`

其中 `theta = cov(Y, X) / var(X)`。该实现使用全样本共同估计 theta，并报告调整前后合并方差变化。生产环境应在实验方案中预先固定协变量、去极值规则与缺失值策略。

## 适用边界

- p-value 使用大样本正态近似，不适合极小样本或极稀疏事件。
- 示例只有两个实验组；多组实验需增加多重比较校正。
- 收入长尾仅作为诊断指标。严谨场景可增加 bootstrap、Delta Method 或分层模型。
- 模拟数据用于演示代码路径，不能作为真实业务结论。
